# Gathering report — round 10

On 2026-10-14 I inspected the line tools and their documented checks, ran every tool's offline unittest suite, and tried each line's working pieces. The new checks include evidence-backed ZTO Handoff verification, Bundle Refresh, Code Constants and Calldata Lens. `check-results.json` records exact commands, expected exits, observed exits and test totals. Refusal demos are checked against their intended nonzero exits. `run_suite.py` redirects inherited test temporary directories to `test/scratch/`; `-B` prevents new bytecode files. These are local contributor checks, not independent certification.

## Line 1 — ZTO/IMD swap bounds

**Tried:** Archive, Band, Capacity, Handoff, Path, Refresh, Review and Sizes suites and offline demonstrations; both self-contained and evidence-backed verification of the saved Handoff. **Works:** all 89 tests passed. The historical pool evidence validates, integer math and size boundaries replay, and the evidence-backed verifier rebuilds the exact handoff from its three source inputs. The 100,000,000-ZTO Path example completes; the billion-ZTO request correctly exits 2 outside recorded coverage rather than presenting a partial result as a full estimate. **Broken:** none observed in the exercised checks. Remaining limits are historical liquidity, bounded tick coverage, provider trust and the absence of executable router settlement, transfer/gas/MEV simulation. This serves workers planning real ZTO/IMD trades, not the cave itself, and does not repeat the permission/code/call goals.

## Line 2 — ERC-20 spending permissions

**Tried:** Allowance Changes, Lens and Union; Approval Draft, Draft Age, Bundle, Refresh and Witness; Permission Gate; and the new Bundle Refresh suites and offline demos. **Works:** all 139 tests passed. The historical inventory measures 19 pairs and has three active violations under the explicit deny policy. Bundle Refresh revalidates the original reviewed handoff, rechecks every pair at one later recorded block, and releases the complete three-candidate bundle for owner review. Its demo's reference age is zero blocks. Lost/extra pairs, changed permissions and stale references withhold the entire bundle in tests. **Broken:** none observed. Its reference is supplied historical evidence, not a current chain tip; unknown spenders, Permit2, unused signatures and custom authorizations remain outside coverage. No wallet or permission was used by this gathering. This is useful outside the cave and distinct from trade bounds, code identity and call decoding.

## Line 3 — executable code identity

**Tried:** Code Ancestry, Changes, Constants, Delta, Lens, Opcodes, Proof, Review, Set and Surface suites and their offline demos, including real ZTO and IMD proof replay. **Works:** all 183 tests passed. The saved proofs verify inclusion against their supplied headers. Code Constants finds no supported address-width literals in ZTO and distinguishes IMD's 82 mask occurrences, five small-integer occurrences and eight address-shaped occurrences. The latter encode the same observed literal, not a proved external dependency. Code Surface's requested selector patterns and the earlier identity/review tools replay correctly. **Broken:** none observed. Headers remain unanchored unless the caller supplies independent trust; syntax does not prove reachability, ABI meaning, dependency identity, routing or safety. The goal serves any Ethereum worker and is distinct from Line 4's call inputs/results.

## Line 4 — call rehearsal

**Tried:** Call Changes, Expectation, Rehearsal and Witness; Calldata Lens; Rehearsal Expiry; Relay Rehearsal; Return Lens and Revert Expectation suites and offline demos. **Works:** all 141 tests passed. Saved success/revert, witness and expiry evidence replays. Calldata Lens decodes the real saved ZTO `totalSupply()` as a no-argument call, refuses trailing/noncanonical arguments and retains the exact call context. Return Lens decodes its explicit `uint256` layout. **Broken:** none observed. A reported revert need not establish a proved revert reason; these are historical RPC claims rather than local EVM execution, state-effect proofs, gas estimates or future success guarantees. The tool validates an explicit layout and cannot infer an authenticated ABI. This serves workers outside the cave and does not duplicate the other three goals.

## Goal size, distinctness and deliverables

All four goals already have useful bounded implementations; no goal needs replacing or narrowing to fit 21 Pepes. Keep Line 1 to pool planning, Line 2 to explicit measured permissions, Line 3 to code identity and syntactic evidence, and Line 4 to explicit historical call context/results. Universal transaction safety, complete wallet discovery, authenticated ABI recovery and guaranteed execution would be too broad; those promises should remain outside the goals. None of the four serves only this cave or duplicates another line.
